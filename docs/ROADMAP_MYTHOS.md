## 总纲：疯要有画面证据

Deshab 的路线不按"功能多少"排，按**能不能被看见**排。
一个改动如果只能被 `grep` 看见，它就不算完成；它必须能在 QEMU 里被看见，
最好能在 60 秒视频里被看见。

**每幕的交付物固定三件：**

| # | 交付物 | 判定 |
|---|--------|------|
| 1 | 原理由（为什么这幕必须存在） | 写进本文件的"疯点"一节 |
| 2 | 工程证据（串口日志 + 截图/帧） | `.build_tmp/<act>_*.log`，路径写进 STATUS.md |
| 3 | 画面证据（一个 60–90 秒的演示片段） | `D:\Vibevideo\deshab-<act>\output\`，无旁白 |

**三不原则：**

1. 不为了好看提前宣布 ✅——⬜ 是坦白，不是装饰。
2. 不在没有回归证据时动启动链——每一幕都要有"上一幕还在"的日志。
3. 不让演示倒逼架构——视频拍的是已经存在的时序，不是想象的时序。

## 🚪 第一幕：敲门（P6b）

**疯点：** 一个"自由"的系统，如果还在每 10ms 去拧门把手，那自由只是轮询的别名。
真正的自由是——门自己会响。

**工程内容**

- IRQ1/IRQ12 解屏蔽（`kern.irq.unmask`），IF=1。
- `shell` / `cmd` / `firstInit` / `login` 的键盘读取从直读端口 `0x60` 切到
  `srv.input.kbd.poll`；鼠标从端口轮询切到 `srv.input.mouse.poll`。
- desktop 任务化：`task_create` + 每帧 `poll` + `sleep_ms`，`[desktop] task slot=N`。

**验收（硬）**

- 串口出现 `[SCHED] enable (LAPIC timer)` 且常驻不 quiesce。
- 在 FirstInit / 登录 / shell / desktop 四个入口都能用真实按键事件操作。
- `grep "inb(0x60)"` 的业务代码命中数归零（驱动内部除外）。
- 无回归：`srv.session.run` → `[desktop] boot` → `desktop ready` 照旧。

**画面证据**：一段"只按键、不打字轮询"的 60 秒：从欢迎页输入名字 → 登录 → shell 输入 `ls` → 桌面点开开始菜单。

**边界**：调度仍是 BSP-only；多核留给第四幕。

## ⚰️ 第二幕：收殓（D1 + R4）

**疯点：** 别的系统卸载驱动叫 unload，Deshab 卸载驱动叫**收殓**——
要念引用计数，要还内存，要把资源一样一样摆回去。

**工程内容**

- DKM 热卸载：引用计数 + 资源回收；循环装载/卸载 100 次不崩。
- R4：segment/system 级 A/B 回滚闭环（page 级已有）。
- 卸载后 `/dev/services` 里对应项消失，消费者 lookup 必须得到明确的 BUS-E04，而不是悬垂指针。

**验收（硬）**

- 100 次循环日志：`unload ok ×100`，无泄漏计数变化，无 panic。
- 回滚演示：人为破坏 B 槽 → 看门狗回滚到 A 槽 → 系统继续跑。
- 一次真实车祸：加载一个坏驱动 → 被拒 → 其余驱动照常。

**画面证据**：屏幕左上角计数 1→100，第 101 次"故意装坏"→ 莲花屏（但是设计内的莲花）。

## 🩻 第三幕：裸奔（D2 + D7）

**疯点：** 一个操作系统最诚实的一刻，是它承认"我现在要执行一段没有任何格式的机器码"。

**工程内容**

- D2 裸机器码加载器：给定物理地址 + 长度，跳进去执行，返回后恢复上下文。
- D7 收尾：kapi 静态表退役，总线成为唯一注册源；block/net 消费者切 `kern.block.*` / `kern.net.*`。
- STUB 基线复核：不新增空实现。

**验收（硬）**

- 一段手写 `mov rax, 42; ret` 被加载并返回 42，串口打印。
- `dkm_kapi_table` 只能通过总线转发，旧名 14 条仍可用（兼容层），但不再直连。
- STUB grep 数 ≤ 基线。

**画面证据**：屏幕打印一段十六进制机器码，回车后返回 `42`。就这两秒，比任何架构图都硬。

## 🏗️ 第四幕：加盖（R5）

**疯点：** 单地址空间里谈多核，就像在同一个房间里放两条传送带——
不是不能，是必须证明两条带子不会把同一只箱子送到两个出口。

**工程内容**

- per-CPU runqueue + 负载均衡；AP 启动（INIT/SIPI）。
- 锁纪律：单地址空间下的自旋锁清单与"谁在持锁时不许睡"白名单。
- 观察点：每个 CPU 的 tick 计数与任务迁移计数。

**验收（硬）**

- QEMU `-smp 2` 启动，两个 CPU 都进入 idle/task。
- 1000 帧内无双重执行（用任务内计数器自检）。
- 单核镜像行为不变（回归）。

**画面证据**：屏幕四角各一个 CPU 心跳数字，四核版四个一起跳。

**风险**：这是全项目最容易翻车的一幕。如果翻车，**允许公开翻车**——
莲花屏 + 串口最后 20 行，正好是第五幕的素材。

## 🪷 第五幕：开光（E1 + E2 + E4）

**疯点：** 仪式感是功能。给空气上锁要咔哒声，开机也要有莲花开的过程。

**工程内容**

- E1 启动莲花动画：不是加载条，是**莲瓣逐层展开**，展开完成 = boot_ok。
- E2 "假想时光键"彩蛋：按住某个组合键，屏幕出现时光回拨的视觉（配合 DRR 回滚）。
- E4 `deshab-fuckyou-edition` 风味 ISO：品牌化构建变体（不改语义，只换气质）。

**验收（硬）**

- 开机动画与 boot 阶段对齐：莲瓣 N = 阶段 N，少一瓣就是少一个 ✅。
- 彩蛋触发后 DRR 回滚真实发生（串口有回滚记录），不是纯视觉。
- 风味 ISO 与 release 功能等价（同一套测试通过）。

**画面证据**：整支宣传片的主镜头。这一暮就是 B 站封面的来源。

## 📣 第六幕：布道（持续）

**疯点：** 把"疯"翻译成人话，但不翻译掉疯。

**工程内容**

- 每幕一支 60–90 秒演示片（无旁白，屏幕文字 + 配乐）。
- 官网 deaicup.com 增加 DeshabOS 专页：状态表直接引用 STATUS.md（唯一事实源）。

**验收（硬）**

- 每支片子开头 3 秒必须出现**真实运行画面**，不是 PPT。
- 每支片子在描述里给出版本号与 STATUS.md 链接。
